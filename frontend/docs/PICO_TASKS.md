# Pico V2.7 页面感知与有界任务

Pico 使用真实业务工具查询数据，通过页面动作白名单操作界面。任务服务每次只推进一个规划决策，前端执行页面动作后回传真实观察和更新后的页面快照；服务端校验观察，再决定下一步。

## 页面读取

`pageSnapshot.ts` 定义版本 1 页面快照和真实路由说明，`usePicoPageAdapter` 按需读取页面当前的业务状态。工厂、设备详情、记录列表/详情、诊断与事件工具、当前研究场景提供业务适配器；其余工具及管理员页面读取白名单中的可见标题、表格、描述和指标。

读取不复制源码、HTML、截图、输入值或认证信息。隐藏、inert、屏幕外、密码和表单、Pico 自身对话不进入快照。研究详情只读取显式标注的可见输出。实体、指标、筛选、选择、可用动作都有限量，传输前限制 15,000 字符，服务端严格限制 16,000 字符。页面快照说明当前界面，不能作为全局最新状态的权威来源。

## 能力目录

`GET /api/v1/pico/task-capabilities` 从可执行的 `TaskReadCall` 与 `PicoUiAction` Schema 生成目录、参数、来源、权限、风险和限制。模型只使用这一目录。前端另做同一协议的运行时防御验证；后端契约测试实际执行前端解析器，检查动作序列化、边界与路径一致性。

只读工具包括当前页面、设备目录和排序、采样、健康历史、事件、报告、研究和比较。页面能力包括真实站内导航、详情标签、工厂筛选及选择、主题和管理员明确字段的预填。没有任意 URL、选择器、JavaScript、SQL、Shell、文件或数据库写入能力。表单预填须由用户检查后自行保存。

## 协议与终止

1. `POST /api/v1/pico/tasks` 接收 `client_task_id`（UUID）、`message`、`context`、`page_snapshot` 和可选 `history`。
2. 返回 `running` 时，前端更新进度、读取最新页面并继续；`awaiting_ui` 每次只包含一个 `ui_action`。
3. 前端执行器重新验证当前账户、权限和实体，通过既有空间导航提交并观察实际路由/选择/主题/表单确认。
4. `POST /api/v1/pico/tasks/{task_id}/continue` 提交 `expected_step`、最新上下文、快照和页面动作结果。失败也如实回传，服务端最多允许一次恢复。
5. `DELETE /api/v1/pico/tasks/{task_id}` 取消任务；开始请求尚未返回时也能通过客户端 UUID 取消。

每次任务最多 8 个规划步骤、12 次读取调用、单读取 4 秒、单模型规划 10 秒、整体 90 秒。前端每次请求 20 秒超时，并检查进度、身份、上下文、重复调用和整体预算。服务端验证排名并列、目标存在性及设备/事件归属。只允许执行一次通过校验的动作，不批量假设后续动作成功。

任务有 `completed`、`partial`、`failed`、`needs_input`、`cancelled`、`unverified` 等明确终态。未配置真实模型时返回 `unverified`；前端保留带显式标记的有限 `/chat` 降级能力。模型决策测试桩只能证明协议和边界，不能证明真实模型自然语言任务质量。

## 会话与部署

任务属于经认证的用户和登录 token 的哈希，不将 token 写入任务、报告或快照。外部页面切换、账户变化、用户取消和关键通知会中止旧请求；执行器自己的导航仅使用一次性、精确身份的票据放行。

任务状态保存在当前后端进程内，十分钟后清理，容量 256；重启后任务失效。当前默认单 worker 部署适用。多 worker 部署必须增加共享任务存储或会话黏性，不能把当前内存状态当作跨进程持久化队列。

## 复验

前端在 `frontend/` 执行 `npm test`、`npm run typecheck`、`npm run build`。后端在 `backend/` 使用已安装依赖及 pytest 的 Python 环境执行 `python -m pytest -q`；任务专项为 `python -m pytest -q tests/test_pico_tasks.py`。测试使用独立临时数据库，不修改开发业务数据。

浏览器需覆盖实际状态筛选、页面快照、每个 UI 动作的执行反馈、连续任务、取消、外部上下文变化和失败观察。真实模型验收需要有效 DeepSeek 凭据，并关闭 mock。不得把降级结果或测试桩结果登记为真实模型通过。
